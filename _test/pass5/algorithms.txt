# Algorithm registry for this shader directory (read by GpuSort at startup).
#
#   algorithm <name>
#   dispatch <file.hlsl> <entryPoint> <groupSize> [NAME=VALUE ...]
#   flush <full|full_legacy|full_ro|code|data|none>   (optional; overrides --flush-mode for this algorithm)
#
# Each 'dispatch' line is one ExecuteIndirect(DISPATCH {numSorts, 1, 1}) of that shader, compiled
# at runtime for cs_6_6 with -O3. The framework always adds -D GROUP_SIZE=<groupSize> and
# -D WAVE_SIZE=<device WaveLaneCountMin> (plus WAVE_SIZE_REQUIRED=1 if the device reports a range of
# wave sizes; see common.hlsli); extra NAME=VALUE tokens become further defines (e.g. the size tier
# bounds MIN_COUNT / MAX_COUNT).
# One group handles one sort (SV_GroupID.x = sort index). The dispatches of an algorithm are
# issued back-to-back WITHOUT barriers, so each one must early-out for sorts outside its tier.
# Flush modes (what happens between the upload and the timed sort; see --help):
#   full        = 256 MB cache flush, then a drain (one-group dispatch + UAV barrier) right before the
#                 start timestamp: shader code and data cold (the default, the measurement of record)
#   full_legacy = full without the drain (the 'full' of pass0-pass4; the flush tail can be timed)
#   full_ro     = read-only 256 MB flush, no drain (diagnostic: is the tail the flush's dirty lines?)
#   code        = flush before the upload, drain: only the code is cold
#   data        = flush, an untimed run of the same dispatches on a private copy, drain: only the data is cold
#   none        = no flush, drain: code and data warm
#
# Bindings (see common.hlsli): b0 root constants, t0 sort descriptors, t1 input, u0 output.
#
# pass5 set: the pass4 shaders (unchanged) with the drained 'full' default, side by side with the
# pass4 method (@legacy), the read-only flush (@ro) and the code / data / none modes.
