# Flush-tail diagnostic set (pass6). Run with --algo-file algorithms_diag_flush.txt (run_all.bat diag:
# --iterations 300 --workload mostly_empty,realistic_mix,worst_case, default wave size only).
# Format: see algorithms.txt. Same shaders as algorithms.txt (no new sort code); only the flush mode
# differs. Suffix = the flush mode.
#
# Question: on the RX 7900 XTX the drained 'full' (pass5 one-group drain) is still ~12 us slower than
# '@data' / '@code' on mostly_empty; cold data and cold code each cost ~0 there, so something after
# the 256 MB flush lasts several us. The spin drains (full_d<N>: an ALU-only dispatch of about N us
# between the flush and the start timestamp, no memory traffic) show how long it lasts: the timing
# should fall to the '@data' level once N covers it. full_ro_d20: the same with a read-only flush
# (is it the dirty write-back?). none_d20: no flush, the spin only (does the spin itself, or the
# GPU idling without the flush work, change the timing? 'none' was slow on large sorts on AMD).

# --- reference: every drain variant ---

dispatch single_pass.hlsl main 1024 RANK_MAX=512 BITREG_MAX=2048 LARGE_RADIX=1
flush full
